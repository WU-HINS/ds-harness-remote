# Repository guide

This repository contains only the self-hosted **server** for DeepSeek Harness
remote access, plus the wire protocol package it depends on.

**The binding engineering contract is the project-root `root.ai.md`** (`../root.ai.md` from here); the copy in
this repository is generated by `pnpm guard --sync` and must never be edited by hand. Read it before changing
anything; where this file and the contract disagree, the contract wins.

This repository is a **minimal server-side implementation** of the upstream protocol
(`liguobao/ds-harness-remote`) plus three deliberate capabilities: OIDC, multi-user accounts, and one account
with many device keys. Anything outside that scope is out of scope by default.

## Layout

- `server/` — HTTP + WebSocket server (accounts, devices, admin UI, sessions).
- `packages/protocol/` — shared frame/RPC schemas (`@dsh-remote/protocol`).
- `web/` — browser assets, bundled by esbuild into `web/dist`.
- `docs/` — operator and API documentation (`docs/api.md` is the API source of truth).
- `scripts/guard/` — static invariants; `root.ai.md` §3 is the contract they enforce.
- `ai-censorship/` — per-commit review records.

## Non-negotiables

1. Schema is declarative: edit `server/src/schema.ts`, keep every statement idempotent.
2. Never log credentials, verification codes, or tokens.
3. Auth changes must ship with a test in `server/tests/`, including a negative case.
4. `pnpm verify` (build → check → guard → test) must pass before committing.
5. A route that exists in `server/src/app.ts` but not in `docs/api.md` fails the gate.
6. Single writer process: do not run two servers against one database.

## Before you call it done

- `pnpm guard` green, and the output pasted into the commit message.
- A review file in `ai-censorship/<name>_review-YYYYMMDD.md` for any change touching auth,
  schema, the gateway, or the API surface.
